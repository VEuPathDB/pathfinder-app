# What was decided

A colocation field nobody states takes the default the site's span form starts on: both
regions exact, every offset 0, every direction `+` (veupathdb-py WDK-STEP-011). Those are
the `ColocationParams` field defaults, so the operator card, FRAME's `set_structure`, the
edit tools and the web editor (which parses the generated schema's defaults) all read one
default.

A COLOCATE node of the spec's structure that states no `colocationParams` holds none
(`StructureNode.colocation_params` is None): it runs the region the join on the graph holds,
else the defaults (`StructureNode.region`). The turn reads that region back from the graph
before it plans (`stated_regions.spec_with_the_regions_it_runs`), so a thread saved before the
plan carried a colocation loads, shows the region WDK runs, and a later edit writes nothing to
its span step.

# Rejected

- **A constant for the operator card beside the model defaults.** The same words built two
  regions, and so two counts, depending on the path that stated them.
- **Refusing a stored COLOCATE node without parameters.** Every thread that held a span
  logic step would end with "This conversation cannot be continued", although the site's
  defaults state what such a node meant.
- **Filling a stored node with the site's defaults on load.** A stored node cannot say whether
  it meant the defaults, and the span step it was built into holds the region the researcher
  chose. The next edit compared that region with the defaults and wrote the defaults over it.
